## R01 NBD 虚拟 exFAT 文件系统实现复杂度与性能

| 维度 | 内容 |
|---|---|
| 风险描述 | 文件访问控制链路为：真实 U 盘 → Linux 挂载层挂载到 `/mnt/usb-control/raw/<session-id>` → Rust NBD 虚拟 exFAT 文件系统层 → f_mass_storage。NBD 虚拟 exFAT 的完整递归目录树、目录项生成、目录簇链、FAT 簇分配、allocation bitmap、超过 4GiB 单文件正常映射、普通文件/目录写回、策略命中 I/O error 反馈和真实 U 盘一致性是整套方案中实现复杂度最高的部分，存在工期风险 |
| 影响 | 高（影响核心功能可用性与研发工期）|
| 概率 | 中（NBD 虚拟 exFAT 文件系统层需从头实现，且需验证 Windows/Linux 对 READ/WRITE 返回 I/O error 的实际表现）|
| 应对策略 | 1. 在真实 RK3568 上持续验证 Linux 挂载层 + NBD + f_mass_storage 链路端到端读写性能（大文件拷贝场景）；2. 独立验证策略命中后 NBD READ/WRITE 返回 I/O error 时 Windows/Linux 的弹窗和重试行为；3. NBD 虚拟 exFAT 文件系统层按正式实现闭环验证完整递归目录树、目录项生成、目录簇链、簇分配、bitmap 管理和超过 4GiB 单文件正常映射；4. 写路径必须覆盖普通文件/目录的新建、修改、删除、重命名、扩容、截断和真实 U 盘一致性，不以只读或部分写回能力替代正式验收；5. 每次 Runtime exFAT 重构必须同时通过 VM 单元/集成测试、交叉编译、RK3568 + 受控 Windows 端到端矩阵和 unmap/remap 后一致性验证 |
| 处理阶段 | 正式核心能力实现阶段，必须在功能合入前完成技术闭环和端到端验收 |

## R02 ClamAV 在 RK3568 上的扫描性能

| 维度 | 内容 |
|---|---|
| 风险描述 | PRD 明确要求 ClamAV 全盘扫描，但 RK3568 ARM 性能有限，大容量 U 盘（128GB+）全盘扫描可能耗时数十分钟，严重影响使用体验 |
| 影响 | 高（扫描未完成前 U 盘不能使用）|
| 概率 | 高（ClamAV 全盘扫描 CPU 密集）|
| 应对策略 | 1. 在 RK3568 上测量真实扫描速度（EICAR + 实际文件）；2. 评估大容量 U 盘扫描耗时对使用体验的影响；3. 本版本仍按 PRD 执行全盘扫描，不增加主动进度通知；4. 扫描期间仅按 PRD 提示扫描状态，完成后再进入映射流程 |
| 处理阶段 | 技术预研阶段 |
